# Бронирование переговорной

Frontend-приложение для бронирования одной переговорной. Пользователь выбирает день, видит расписание и может создать, изменить или удалить бронь. HTTP API имитируется через MSW прямо в браузере.

## Стек

- React 19 и TypeScript 6, сборка через Vite 8.
- TanStack Query — загрузка, кеширование по дате и мутации.
- React Hook Form — форма и ошибки полей; правила проверяет общая функция `validateBooking`.
- Tailwind CSS 4 через `@tailwindcss/vite`.
- MSW 2 — mock API; отдельное хранилище в памяти.
- Vitest, Testing Library и jsdom — модульные и интеграционные тесты.
- Playwright — E2E; Oxlint — линтер; pnpm — менеджер пакетов.

Версии зависимостей и команды проекта указаны в `package.json`, точные версии зафиксированы в `pnpm-lock.yaml`.

## Установка и запуск

Требуются Node.js 22.12 или новее и pnpm 10.33.0 — версия pnpm указана в поле `packageManager`. Установленный Vite также поддерживает Node.js 20 начиная с 20.19.

Из корня проекта:

```sh
pnpm install
pnpm dev
```

Откройте адрес, напечатанный Vite в терминале. Отдельный backend и переменные окружения не нужны. MSW запускается до рендера React и работает как в разработке, так и в production demo.

## Тесты

```sh
pnpm test
pnpm lint
```

Vitest проверяет правила дат и интервалов, граничные длительности, пересечения, CRUD и ошибки API, состояния страницы, сохранение полей и повторную отправку после конфликта.

Перед первым запуском E2E установите браузер для Playwright:

```sh
pnpm exec playwright install chromium --no-shell
pnpm test:e2e
```

Playwright сам выполняет сборку, запускает preview на `http://127.0.0.1:4175` и останавливает его после тестов. Порт 4175 должен быть свободен. Каждый тест получает отдельный браузерный контекст и работает с MSW приложения, без подмены ответов в E2E.

Время фиксируется до загрузки страницы: **9 октября 2026, 08:00, Asia/Bishkek**. Это настройка тестов; в обычном приложении используются реальные часы браузера.

На ширинах 1280 и 375 px проверяются:

- создание → редактирование → удаление с подтверждением;
- серверный 409 при создании и редактировании, сохранение полей и успешная повторная отправка;
- управление клавиатурой, видимый фокус и его перенос при редактировании и отмене;
- отсутствие горизонтального переполнения, в том числе с длинным названием и ошибкой формы.

HTML-отчёт сохраняется в `playwright-report/`, скриншоты и артефакты ошибок — в `test-results/`. Эти каталоги исключены из Git. Просмотр отчёта:

```sh
pnpm exec playwright show-report
```

## Реализованные функции

- Выбор даты; по умолчанию — сегодня. Прошедшие дни доступны для просмотра. Список отсортирован по времени начала; при смене даты брони предыдущего дня не выдаются за данные нового.
- Состояния загрузки, пустого списка и ошибки с кнопкой «Повторить».
- Создание брони: необязательное название, время начала и окончания. Дата берётся из выбранного дня.
- Редактирование через ту же форму с кнопками «Сохранить» и «Отмена». Текущая бронь исключается из проверки пересечений по id. Смена даты закрывает редактирование.
- Удаление с подтверждением браузера. При удалении редактируемой брони её форма закрывается; черновик другой брони сохраняется.
- Ошибки рядом с полями. При ошибке сохранения введённые значения и режим редактирования сохраняются; при ошибке удаления бронь остаётся в списке.
- Во время сохранения или удаления заблокированы другие операции записи, выбор даты и переключение брони. Сохранение также недоступно, пока список загружается или его загрузка завершилась ошибкой.
- После успешной записи список обновляется. После серверного 409 он запрашивается повторно; сбой обновления показывается отдельно и не выдаётся за успешное обновление.
- Адаптивная вёрстка, подписи полей и заметный фокус с клавиатуры.

## Правила бронирования и время

Дата должна существовать и иметь формат `YYYY-MM-DD`, время — `HH:mm`. Начало и окончание должны попадать в **09:00–18:00**, начало строго раньше окончания. Длительность — **30–120 минут включительно**. Обязательного шага 30 минут нет: например, 10:15–10:45 допустимо.

Нельзя сохранять интервал с началом в прошлом. Проверка использует текущее время при отправке, включая секунды: в 10:15:20 начало 10:15 уже считается прошедшим. Пересечения проверяются только на выбранную дату. Соседние интервалы, например 10:00–11:00 и 11:00–12:00, разрешены.

Все даты и часы интерпретируются в **локальном часовом поясе браузера**. В данных нет отдельного часового пояса или UTC-смещения; проверки зависят от часов устройства. Одинаковые правила применяются в форме и в mock API.

## Хранение и mock API

Начальный список пустой. Брони хранятся в `Map` в памяти текущей вкладки. **Перезагрузка страницы удаляет все брони и сбрасывает демо-переключатель.** Данные не сохраняются в localStorage или базе данных и не синхронизируются между вкладками и пользователями.

UI обращается к API через `fetch` в `src/features/bookings/api.ts`. Хранилище находится отдельно, в `src/mocks/bookings-store.ts`, обработчики — в `src/mocks/handlers.ts`.

| Метод | URL | Успешный ответ |
| --- | --- | --- |
| GET | `/api/bookings?date=YYYY-MM-DD` | `200`, брони выбранной даты по времени начала |
| POST | `/api/bookings` | `201`, созданная бронь с id |
| PATCH | `/api/bookings/:id` | `200`, обновлённая бронь |
| DELETE | `/api/bookings/:id` | `204`, без тела; клиент не читает JSON |

POST принимает `date`, `start`, `end` и необязательный `title`. PATCH объединяет переданные поля с существующей бронью. Перед проверкой правил обработчики проверяют JSON, типы и допустимые поля; `id` в теле не принимается.

Ошибки имеют вид `{ code, field?, message }`: `400` — неверные данные, `404` — бронь не найдена, `409` — пересечение. Обычно ошибочный запрос не меняет хранилище. Исключение — включённый демо-сценарий ниже: он намеренно добавляет чужую бронь перед ответом 409, но не сохраняет отправленные пользователем изменения.

## Как воспроизвести конфликт 409

1. Выберите **завтрашнюю дату**, чтобы сценарий не зависел от текущего времени. Убедитесь, что 10:15–10:45 свободно.
2. Раскройте «Демо-сценарии» и включите «Конфликт при следующем сохранении».
3. Заполните название, начало **10:15**, окончание **10:45** и нажмите «Забронировать».
4. После обычной валидации mock API добавит «Бронь другого участника» на этот интервал и вернёт 409. Переключатель выключится автоматически.
5. В обновлённом списке появится чужая бронь. Поля останутся заполненными, рядом со временем начала появится: «Это время уже заняли. Список обновлён — выберите другой интервал».
6. Выберите другой свободный интервал, например **11:00–11:30**, и повторите отправку. Бронь сохранится, форма очистится.

Для отдельной проверки PATCH перезагрузите страницу (все брони сбросятся) и снова выберите завтра. Создайте бронь **09:00–09:30**, затем нажмите «Редактировать». Включите переключатель и замените время на свободное **10:15–10:45**. После «Сохранить» появится тот же 409; поля и режим редактирования сохранятся, исходная бронь не изменится. Выберите свободное **11:00–11:30** и сохраните повторно.

Сценарий одноразовый: его расходует только валидный POST или PATCH на полностью свободный интервал выбранной даты. Перед добавлением чужой брони проверяются все существующие брони, включая редактируемую. Касание границ разрешено, брони других дат не мешают сценарию.

Если при редактировании время осталось прежним или новый интервал пересекается с исходной бронью, выполняется обычное сохранение, чужая бронь не добавляется, а переключатель остаётся включённым. Например, бронь **10:00–11:00** можно сохранить без изменения времени или перенести на **10:30–11:30** (если нет пересечения с другими бронями). Следующий перенос на полностью свободное **12:00–13:00** вызовет демо-конфликт 409.

Неверные поля и пересечение с другой бронью не обходят обычную валидацию и не расходуют переключатель. Если обновление списка после 409 не удалось, отображается отдельная ошибка; сначала нажмите «Повторить» у списка.

## Ограничения текущей версии

- Поддерживается одна переговорная, без выбора комнаты, авторизации, владельцев броней и прав доступа. Любую видимую бронь можно редактировать или удалить с учётом правил времени.
- Реального backend и постоянного хранения нет. Демо-конфликт имитирует запись другого участника; настоящего многопользовательского взаимодействия нет.
- Расписание 09:00–18:00 фиксировано для всех дат. Выходные и праздники не исключаются. Повторяющиеся и переходящие через полночь брони не поддерживаются.
- Через форму нельзя перенести бронь на другую дату: смена дня завершает редактирование. В API PATCH поле `date` поддерживается.
- Сохранить бронь с началом в прошлом нельзя даже при редактировании только названия. Прошедшую бронь можно просмотреть или удалить.
- Список не обновляется через push-события или периодический опрос. Кеш и повторные запросы TanStack Query не заменяют синхронизацию между пользователями.
- Проверка E2E настроена только для Chromium, на ширинах 1280 и 375 px. Firefox, WebKit и реальные мобильные устройства этим набором не проверяются.
- Mock API включён и в production-сборке. Запросы используют абсолютный путь `/api/bookings`; отдельный адрес backend не настраивается. Демо рассчитано на размещение в корне сайта.
